# SKYGUARD AI — ACTION SEMANTICS MATRIX

This document provides the unambiguous semantic specification for all user- and system-triggered actions in SkyGuard AI across all 9 application pages.

| Action Name | Target Endpoint | Database Mutation (TimescaleDB) | Local In-Memory Buffer Mutation | Provider / Ingestion Behavior | UX / Visual State Transition |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Refresh** | `POST /api/refresh-live` | **None** (Readings appended normally upon arrival) | None wiped; fresh tick appends to chart | Asynchronously triggers provider snapshot (`sim.refresh_live_now()`) | Topbar spinner rotates; no data blanks; cards and charts update seamlessly upon ingestion |
| **Reset DB** | `POST /api/admin/clear-history` (`target="all"`) | **`TRUNCATE TABLE sensor_readings; TRUNCATE TABLE station_health_events;`** | Pristine purge: `sim.latest.clear()`, `sim.trend_history.clear()`, `sim.recent_anomalies.clear()`, `reset_detection_state()` on all 28 buffers | Triggers immediate Open-Meteo live snapshot fetch; repopulates all 28 stations with live readings | UI displays `"Synchronizing live telemetry..."` transitional state (HTTP 200 with `is_syncing: true`); zero 404 error banners; restores pristine live readings in ~0.5s |
| **Purge Replay History** | `POST /api/admin/clear-history` (`target="replay"`) | **`DELETE FROM sensor_readings WHERE source = 'replay';`** (Live data preserved) | Replay points filtered out from `trend_history` & `recent_anomalies`; Live memory retained | None (Replay engine idle or stopped) | Benchmark replay points turn off; live chart retains genuine historical baseline |
| **Return to Live** | `POST /api/system-mode` (`mode="live"`) | `DELETE FROM sensor_readings WHERE source = 'replay';` | Resets all 28 station buffers (`reset_detection_state()`); wipes replay circuit breaker trips | Restores live latest snapshot (`sim.latest = dict(sim._last_live_latest)`); schedules provider refresh | Header badge switches from `"Replay Mode (Benchmark)"` to `"Live Mode (TimescaleDB)"`; station health rehydrates to `HEALTHY` / `NORMAL` instantly |
| **Start Replay / Inject Fault** | `POST /api/inject-anomaly` | Writes benchmark ticks with `source='replay'` | Initializes replay frames and sets `sim.mode = "replay"` | Ingests benchmark replay records at 2s cadence | Header badge switches to `"Replay Stream (2s)"`; anomalies recorded with root-cause attribution |
| **Mark Repaired** | `POST /api/repair-sensor` (`force_recovery=false`) | None | `buf.mark_repaired(ts)`; sets `recovery_active=True`, clears counters | Next readings evaluated for clean streak (5 consecutive clean readings required) | Sensor enters monitored recovery mode; status badge updates to `REPAIRING` |
| **Force Recover** | `POST /api/repair-sensor` (`force_recovery=true`) | None | `buf.force_recover()`; flips health instantly to `HEALTHY` | Resets parameter circuit breakers to nominal | Instant flip to `HEALTHY` (100%); zero waiting period |
